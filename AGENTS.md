# Правила проекта

- Используйте development-quality для доработок и проверяйте итоговый diff.
- Python-тесты пишите на pytest в отдельных `tests/test_*.py`, по одному поведению на тест. Общую подготовку и очистку БД, приложения, сервера и клиентов выносите в `tests/conftest.py`. HTTP-тесты получают готовые клиенты, проверяют ответы и работают с изолированными данными. Для временных файлов используйте `tmp_path`.
- Обработчики FastAPI принимают запрос и возвращают ответ. Правила магазина и авторизации размещайте в сервисных модулях. Сложные ветвления выделяйте в функции с предметными именами. При рефакторинге сохраняйте порядок валидации, форматы ответов и границы транзакций.
- При изменении JSON API обновляйте схему Swagger на `/docs` и проверяйте её в pytest.
- Используйте uv и Python 3.12. Запуск — `uv run --locked python main.py`. Упаковка — `uv run --locked python main.py --pack`. Проверки — `uv run --locked pytest -q` и `node tests/shop.test.cjs` (или `make test`).
- После изменения зависимостей обновите `uv.lock` через `uv lock` и экспортируйте зависимости контейнера командой `uv export --locked --format requirements.txt --no-dev --no-emit-project --no-header --no-hashes --no-annotate --output-file requirements.txt`.
- Сценарий Compose проверяется отдельно в CI. Он пересоздаёт контейнер тестового стека.

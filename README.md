# CZUZE — учебный магазин с авторизацией

[Отчёт тимлида и путеводитель по структуре проекта для команды](REPORT.md).

Основа проекта защиты веб-ресурса от ботов. Исходный магазин: https://github.com/itmo-workshop-09-11-2026/Czuze (коммит f1c84a2). Этот репозиторий содержит фундамент тимлида: FastAPI, главную, регистрацию, вход, SQLite, тесты и CI. Пять антибот-защит и бонусную задачу добавляют участники команды.

## Локальный запуск

Самый простой вариант — установить и запустить Docker Desktop (на Linux — Docker Engine с Compose v2). Из корня проекта:

```sh
docker compose up --build
```

Открыть http://localhost:8000. Python, Node.js и `.env` для этого варианта не нужны. Чтобы запустить в фоне: `docker compose up --build -d`. Логи: `docker compose logs -f`. Остановка: `docker compose down`.

Пользователи, сессии, заказы и остатки сохраняются в именованном томе `shop-data` между остановками и пересозданием контейнера. Это отдельная база: существующая локальная `data/shop.sqlite3` автоматически не импортируется. Не добавляйте `-v` к команде остановки, если нужно сохранить данные.

Если порт 8000 уже занят локальным Python-сервером, остановите его или задайте `HOST_PORT=8001` в `.env` рядом с `compose.yaml`, затем повторите запуск и откройте http://localhost:8001. Для Compose `.env` необязателен и читается автоматически. После изменения кода повторите `docker compose up --build`.

### Запуск без Docker

Нужны Python 3.12+; для JavaScript-тестов — Node.js 22+. Из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python main.py
```

Windows: `py -3.12 -m venv .venv`, затем `.venv\Scripts\activate`.
Открыть http://localhost:8000. Остановка — Ctrl+C. Можно использовать `make run` с активированным окружением. `.env.example` описывает переменные, но `.env` автоматически не загружается: задавайте переменные в оболочке.

Стек: FastAPI/Uvicorn, HTML/CSS/JS, Jinja2, SQLite (`sqlite3`), Argon2 (`pwdlib`), pytest/httpx. Без отдельного frontend-сервера. Каталог, корзина и избранное доступны гостям; подтверждение заказа требует входа. После входа корзина сохраняется.

## Маршруты и данные

- `GET /` — магазин; `GET/POST /register`, `GET/POST /login` — HTML-формы `username`, `password`, `csrf`, необязательный `next=checkout`.
- Логин: 3–32 латинских буквы, цифры или `_`, без учёта регистра; пароль: 8–128 символов. Успешная регистрация сразу выполняет вход. Успех — redirect 303; неверные данные — 422, занятый логин — 409, неверный пароль — 401.
- `GET /api/auth/me` — `{user: {id, username} | null, csrf}`; `POST /logout` — HTML-форма с `csrf`.
- `GET /api/products?q=утка&category=Отладка` — каталог.
- `POST /api/orders` — JSON `{items: [{productId, quantity}], promo?, requestId?}`, cookie сессии и `X-CSRF-Token` из `/api/auth/me`. Без входа — 401, неверный CSRF — 403. Повтор с тем же составом и владельцем возвращает прежний заказ. `DEBUG10` даёт скидку 10%.
- `PUT /api/products/{id}` — прежний административный API с `X-Admin-Token`; поля `name`, `price`, `category`, `description`, `image`, `stock`. Отключён без `SHOP_ADMIN_TOKEN`.

По умолчанию БД создаётся в `data/shop.sqlite3`; `SHOP_DB` меняет путь, вне `site/`. Старые товары и заказы сохраняются; старые заказы не назначаются пользователям. Сервер хранит хеши паролей, хеши токенов сессий и владельцев новых заказов. Сессии действуют 24 часа; выход отзывает сессию. История заказов показывается из локального хранилища отдельно для каждого аккаунта, между устройствами не синхронизируется. Корзина общая для браузера. Старую анонимную историю не присваиваем аккаунту.

`HOST` по умолчанию `127.0.0.1`, `PORT` — `8000`. `COOKIE_SECURE=1` включайте для HTTPS; локальный HTTP использует `0`. Секреты, базы, кэши и рабочие заметки не коммитим.

## Проверки и защита проекта

```sh
python -m pytest -q
node tests/shop.test.cjs
python tests/smoke.py
# либо всё вместе:
make test
```

Сессионная фикстура pytest запускает настоящий Uvicorn на свободном порту с временной БД, ждёт готовности и завершает процесс. Остальные HTTP-тесты используют TestClient и временные базы. CI выполняет проверки на Linux и Windows с Python 3.12. Тесты покрывают главную и формы, регистрацию, вход/выход, CSRF, истечение сессий, владельца заказа, повторные запросы, миграцию БД, остатки, транзакции, ZIP и изоляцию файлов. Отдельная задача CI собирает и запускает Compose; `tests/compose_smoke.py` проверяет страницы и сохранение аккаунта, сессии, заказа и остатков после пересоздания контейнера. Этот скрипт предназначен для тестового стека: он создаёт аккаунт и заказ, затем пересоздаёт контейнер.

Для демонстрации: открыть каталог гостем → добавить товар → подтвердить заказ → зарегистрироваться → вернуться к оформлению → оформить → проверить историю → выйти. На защите показать `pytest` и зелёный CI.

## Подключение команды

`webapp.create_app()` собирает приложение, `shop_api.py` содержит правила магазина. Сетевой щит добавляет middleware до обработчиков: фильтрация IP дата-центров, лимит запросов, User-Agent. Функция `webapp.client_ip(request)` — точка подмены IP через monkeypatch; сервер не доверяет произвольному X-Forwarded-For.

Пара форм работает с `templates/auth.html` и обработчиком `authenticate`: honeypot и учебная ложная инструкция в HTML, проверки до создания пользователя/входа. Бонус — проверка времени заполнения либо бот-симулятор. Эти механизмы пока не реализованы. Для подмены IP/времени и проверки заголовков используйте отдельные тесты с TestClient и monkeypatch.

Каждая пара работает в своей ветке, открывает PR в `main` и прикладывает тесты. Тимлид объединяет изменения после проверки CI. Для начала: клонировать репозиторий, установить зависимости, запустить сайт и тесты.

## ZIP и Docker

`python main.py --pack` / `make pack` создаёт `shop.zip`: автономная статическая демоверсия магазина без серверной авторизации. GitHub Pages автоматически не публикуется. Рабочий вход доступен через FastAPI.

Для обычной работы используйте `docker compose up --build`: том базы и проверка готовности уже настроены в `compose.yaml`. Старые команды `make docker-build` и `make docker-run` оставлены для ручного запуска одиночного контейнера; они не подключают постоянный том.
